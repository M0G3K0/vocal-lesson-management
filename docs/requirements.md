# 要求書

## 文書の位置づけ

この文書は、SHEERの予約に関する個人向けサービスについて、これまでの会話から確認できる要求を整理したものです。

要求と、設計・仕様・実装方法は分けて管理します。この文書では、使用する技術、データ構造、画面構成、外部サービスとの接続方法は決定しません。

また、別AIが作成した要求草案に含まれる `Must` / `Should` / `Can` の優先度は、本人との合意がないため採用していません。

## 1. 利用者と対象範囲

- 利用者は本人一人とする。
- 一般公開サービスや複数ユーザー向けサービスは対象としない。
- スマートフォンとPCの両方から利用できるWebサービスを目指す。
- SHEERの予約を利用する本人が、自分の予約・予定・移動を扱うためのサービスとする。

## 2. 目的

SHEERの予約を、現在より使いやすく管理できるようにする。

長期的に実現したいことは次のとおりです。

- SHEERの予約情報を取得する。
- レッスン予定をGoogle Calendarへ登録する。
- 自宅からスタジオまでの移動時間を予定に反映する。
- スマートフォンからSHEERの空き枠を探しやすくする。
- 将来的に、予約操作自体を簡単にする。

## 3. 確認できている要求

### 3.1 予約情報

- 本人がSHEERの予約情報を確認できるようにする。
- SHEERを予約情報の対象サービスとする。

予約一覧で確認したい情報の具体的な項目は、SHEERの画面調査後に確定します。

### 3.2 カレンダー

- レッスン予定をGoogle Calendarで管理できるようにする。
- レッスン予定には、予約に関係する日時やスタジオなどの情報を扱えるようにする。

Google Calendarへの登録タイミング、イベントの詳細項目、重複登録の扱いは未確定です。

### 3.3 移動

- 自宅からスタジオまでの移動時間を扱えるようにする。
- レッスン予定と移動予定を、Calendar上で確認できる形にすることを目指す。

出発地点の選択方法、到着余裕時間、移動予定を独立イベントにするかどうかは未確定です。

### 3.4 空き枠検索

- スマートフォンから、SHEERの空き枠を探しやすくする。

検索条件、絞り込み方法、サービス内で空き枠を取得・表示するかどうかは未確定です。

### 3.5 将来の予約支援

- 将来的に、SHEERの予約操作自体を簡単にする。

初期段階では、候補を確認したうえで公式予約ページに進み、最終確定は本人が行う方式が安全な方向性として示されています。ただし、これを最終的な画面仕様として確定したものではありません。

## 4. 安全性・情報管理に関する要求

- 本人以外が予約情報を見られないようにする。
- SHEERのパスワード、Cookie、Google OAuthトークン、APIキーなどの秘密情報をGitHubへ保存しない。
- 自宅住所などの個人情報を公開しない。
- 情報が不足している、または内容が曖昧な状態で、予約やCalendar登録を勝手に確定しない。
- 自動操作を行う場合でも、誤予約につながる可能性がある状態では停止できるようにする。

## 5. 業務上の既知情報

以下は要求そのものではなく、現時点で把握している前提・参考情報です。

- 公式ページ上では、レッスンは1コマ45分とされている。
- 吉祥寺校の住所は「〒180-0003 東京都武蔵野市吉祥寺南町1-5-7 雪ビル5F」である。
- ただし、すべてのスタジオの情報やレッスン条件が同じとは限らない。

## 6. 初版について確認できていること

- キャンセル連携は、初版の必須機能ではなくstretch候補である。
- 予約の完全自動化は、初期段階で確定した要求ではない。
- 予約情報の取得方法、空き枠取得方法、予約確定の通信、CSRF、CAPTCHA、利用規約などは未調査である。

初版の機能範囲そのものは、まだ確定していません。

## 7. 別AIの草案から、要求として確定していないもの

次の内容は、目的から考えると有用な候補ではありますが、最初の会話では合意されていません。

- 予約情報に必ず含める項目を「日時・スタジオ・レッスン内容・講師・時間・状態」と固定すること。
- 同じ予約を重複登録しないという具体的なCalendar仕様。
- スタジオ、講師、レッスン内容、曜日、時間帯による絞り込み。
- 自分の好み、優先順位、よく使うスタジオなどの登録。
- 空き枠や予約手続きに関する通知。
- 予約変更を自動でCalendarへ反映すること。
- キャンセルされた予約をCalendarから自動削除すること。
- 出発時刻、到着時刻、乗換、運賃、距離などを必ず表示すること。
- 日本時間を正式なシステム要件とすること。
- 無料利用を正式な要求とすること。
- 帰宅経路、自宅以外の出発地点、複数の予約サービスへの対応。
- ネイティブスマートフォンアプリの提供。

複数ユーザー対応については、対象範囲を本人一人とする方針と合わないため、現時点の要求には含めません。
