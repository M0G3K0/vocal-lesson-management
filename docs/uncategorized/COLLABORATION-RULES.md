# 協働ルール（暫定）

## 合意の扱い

- AIの提案は、ユーザーが明示的に合意するまで未合意とする。
- 沈黙や曖昧な返答から合意を推測しない。
- 合意した内容と未決定の内容を区別して記録する。
- 提案への合意は、その内容への合意を意味する。後続の操作まで許可されたとは解釈しない。

## 作業と反映の指示

- AIは、作業に着手する前に目的・進め方を提案し、ユーザーの指示を待つ。
- いつ内容を記録・反映するかはAIが自動判断せず、ユーザーの指示に従う。
- 指示された場合も、その対象と範囲を越えて作業しない。

## GitHub Issue

- AIは、ユーザーから明示的に依頼されない限り、GitHub Issueを作成・編集・コメント・Close・Reopenしない。
- IssueやGitHub Projectsへの書き込みを行う場合、ユーザーの指示に対象と内容が明確に含まれていれば、その指示を許可として扱い、追加確認しない。内容が未確定なら、関連する操作をまとめて対象と最終的な内容・フィールド値を提示し、一度だけ明示的な承認を得る。そのOKは提示したすべての書き込みを許可する。内容への合意と書き込み許可を別々に確認せず、同じ内容について二度目の承認を求めない。承認後に内容や対象が変わった場合は、その変更分について改めて確認する。
- Issueに記載する文面の案は、チャットで提示できる。

## ドキュメントとGitHub Projects

- 半永続的な決定事項を文書化するときは、ユーザーの指示に基づいてAIが文書作成・更新を支援する。
- GitHub Projectsの項目追加やフィールド更新は、ユーザーから指示された範囲で行う。操作方法は[GitHub Projects操作ガイド（AI向け）](./GITHUB-PROJECTS-AI-OPERATIONS.md)に従う。
- 人間がすべての動作確認項目をOKにした後、AIはコミットごとの内容・順序・メッセージ案を提示し、ユーザーのGOを得てからその計画どおりにcommitする。コミット数やメッセージ形式は固定しない。
- commit後、AIは`git status`とPull Requestのタイトル・本文案をユーザーに提示する。pushとPull Requestの作成はユーザーが行う。
- Mergeはユーザーが行う。

## 今後の仕組み化

ここに記載した取り決めを技術的に強制する方法は、別途検討する。現時点では、この文書に運用上の取り決めを記録する。
