# 文書化ルール（暫定）

## 文書化の対象

- GitHub Issue完了後も参照する価値がある内容は、必要に応じて文書化する。
- すべてのGitHub Issueに個別のドキュメントを作成するわけではない。
- 要求書や仕様書が必要になる場合でも、すべてのGitHub sub-issueに個別の文書を作成するとは限らない。

## 文書化の判断軸

GitHub Issue完了時などに、次の4軸で文書化の必要性を判断する。

- 再利用性
- 持続性
- 影響
- リスク

各軸を高・低で確認し、次の基準で扱う。

- 2軸以上が高い場合は文書化する。
- 影響またはリスクが特に高い場合は文書化する。
- すべて低い場合は、GitHub Issue内に残す。

## 文書化のタイミング

- 原則として、決定がなされた時点で文書化する。
- すぐに文書化することが難しい場合は、文書化用のGitHub sub-issueを作成する。
